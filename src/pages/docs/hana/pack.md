自分が作ったプログラムを友達に渡すとき、普通は「まずHanaをインストールしてください」と言わなければなりません。`hana pack`はそれをなくしてくれます。プログラムを**実行ファイル1つ**にまとめるので、受け取った人はHanaなしで、ダブルクリックするか、ターミナルで名前を打つだけで実行できます。

### まとめてみる

```bash
hana pack アプリ.knd
```

同じフォルダに`アプリ.exe`（Windows）または`アプリ`（LinuxやMac）ができます。名前を決めるには`-o`を使います。

```bash
hana pack アプリ.knd -o マイアプリ
```

ハジャのプログラム（`.hr`）も同じようにまとめられます。まとめる前に`hana run --bc アプリ.knd`で動かしてみると、まとめたあとと同じ方式（バイトコード）で確認できます。

### 中には何が入っているの？

まとめたファイルは、3つをつなげたものです。

- **小さなランタイム**: プログラムを動かすのに必要なものだけを入れた`hana-runtime`（約6MB）です。ソースを読むパーサーや言語サーバーは入っていません。
- **プログラム**: ソースをあらかじめコンパイルしたバイトコードです。持ってきたカナデ・ハジャのファイルや、[`hana add`で取ってきたパッケージ](/docs/hana/packages)のコードもこのときに一緒に入ります。なので、受け取る人にソースファイルや`hana.json`は必要ありません。
- **ネイティブライブラリ**（あれば）: パッケージがネイティブライブラリを使うなら、一緒に用意されます。

`hana pack`を使うには、`hana`実行ファイルの**隣に`hana-runtime`が必要です**。Hanaを自分でビルドしたなら、READMEの案内どおりに`hana-runtime`も一緒に作っておいてください。

### ネイティブライブラリはどこに置くの？

標準では、実行ファイルの隣の`libraries/`フォルダです。まとめた実行ファイルとこのフォルダを一緒に渡す必要があります。

```bash
マイアプリ.exe
libraries/
└── http_server.dll
```

フォルダなしでファイル1つだけを渡したいなら、`--embed`を付けます。ライブラリが実行ファイルの中に圧縮されて入り、最初に実行するときにユーザーのキャッシュフォルダに1回だけ展開されます。

```bash
hana pack サーバー.knd --embed
```

### ほかのOS向けに作る

`--target`で、ほかのOSやCPU向けの実行ファイルを作れます。WindowsでLinux向けを作る、といった使い方です。

```bash
hana pack アプリ.knd --target linux-amd64
```

そのプラットフォーム向けのランタイムが必要です。`hana`の隣に`hana-runtime-linux-amd64`という名前で置くか、`--runtime`でパスを教えてください。ランタイムはHanaのソースから、`GOOS=linux GOARCH=amd64 go build -o hana-runtime-linux-amd64 ./cmd/hana-runtime`のようにして作ります。

### オプションのまとめ

| オプション | できること |
| --- | --- |
| `-o 名前` | 作る実行ファイルのパス。省略すると入力ファイルの名前を使います |
| `--embed` | ネイティブライブラリを実行ファイルの中に入れます |
| `--target プラットフォーム` | `windows-amd64`、`linux-arm64`のように、作るプラットフォーム |
| `--runtime ファイル` | ベースにする`hana-runtime`ファイル |

### 知っておくこと

- まとめたプログラムはバイトコードエンジンで動きます。バイトコードエンジンが対応していない機能（変数の名前を文字列から作って呼ぶ動的な呼び出し）は、まとめたプログラムでは使えません。`hana run --bc`で事前に確認してください。
- プログラムが読むデータファイル（`【ファイル】`で開くファイルなど）はまとめられません。実行するコンピューターに別に置いておく必要があります。
- コード署名が必要なら、**まとめたあとで**署名してください。実行ファイルの後ろに何かを付け足すと、署名が壊れます。
