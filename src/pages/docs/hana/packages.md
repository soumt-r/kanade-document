パッケージは、誰かが（あるいは自分が）作っておいた関数とクラスのまとまりです。[Hanaランタイム](/docs/hana/intro)には、パッケージをダウンロードして管理するコマンドが入っています。パッケージは**gitリポジトリ**で、名前がそのままリポジトリのアドレスです。中央サーバーはありません。ブラウザの実行ボタンではパッケージは使えず、Hanaランタイムで実行するときだけ使えます。

### パッケージを使う

プロジェクトのフォルダでパッケージを追加します。`git`がインストールされている必要があります。

```bash
hana add github.com/owner/repo
```

この1行がすることは次のとおりです。

- リポジトリの`v1.2.0`や`1.2.0`のような**バージョンタグ**のうち、一番高いものを選びます。
- そのバージョンを自分のコンピューターのキャッシュフォルダ（`~/.hana/pkg`）にダウンロードします。フォルダは環境変数`HANA_HOME`で変えられます。
- そのパッケージが必要とするほかのパッケージも一緒にダウンロードします。
- プロジェクトのフォルダに`hana.json`と`hana-lock.json`を書きます。

バージョンを自分で決めるには`@`を付けます: `hana add github.com/owner/repo@1.2.0`。

あとは、リポジトリのパスをそのまま【】の中に書いて持ってきます。ほかの[標準モジュール](/docs/tutorial/10-stdlib)とまったく同じ見た目です。

```kanade skip
【github.com/owner/repo】から〈挨拶〉を持ってこよう
〈挨拶〉(「カナデ」)を出力しよう
```

パッケージは、ハジャ用とカナデ用のエントリポイントを別々に持てます。自分のスクリプトの言語に合うエントリポイントがないと、「この言語のエントリポイントがありません」というエラーになります。

### hana.jsonとhana-lock.json

```json
{
  "dependencies": {
    "github.com/owner/repo": "1.2.0"
  }
}
```

`hana.json`は**自分が求めるもの**です。書かれたバージョンは「このバージョン以上」を表す最小バージョンです。`^`や`~`のような範囲の書き方はありません。

```json
{
  "github.com/owner/repo": {
    "version": "1.3.4",
    "commit": "a1b2c3d4e5f6..."
  }
}
```

`hana-lock.json`は**実際に選ばれたもの**です。正確なバージョンと、そのときそのバージョンのタグが指していたコミットが書かれます。自分が追加したパッケージだけでなく、そのパッケージが必要とするパッケージもすべて入ります。2つのファイルをgitに一緒に上げておけば、別のコンピューターで`hana install`を1回実行するだけで、同じバージョンがダウンロードされます。

同じパッケージが複数の場所から別々の最小バージョンで求められたら、求められたうちで**一番高いバージョン**を1つだけ選びます。最小バージョンだけを書くので、「条件が合わなくてインストールに失敗する」ことはありません。

### 別のコンピューターで、そのほかのコマンド

| コマンド | できること |
| --- | --- |
| `hana install` | `hana-lock.json`に書かれたパッケージをすべてダウンロードします。lockが`hana.json`に足りなければ、バージョンを選び直します |
| `hana remove github.com/owner/repo` | パッケージを外します。そのパッケージのためだけに必要だったものもlockから消えます |
| `hana list` | 使っているパッケージとバージョンを表示します。`*`は自分で直接追加したものです |

`hana run`は**何もダウンロードしません**。パッケージがインストールされていなければ、「インストールされていません」というエラーで`hana install`を案内します。lockに書かれたコミットと実際にダウンロードしたコミットが違う場合（誰かがタグを動かした場合）は、インストールを拒否します。

### 自分のコンピューターにあるパッケージを直しながら使う

パッケージを作りながら、そのパッケージを使うプロジェクトも一緒に直すときは、`hana.json`に`replace`を書いて、ダウンロードの代わりに自分のフォルダを指すようにします。

```json
{
  "dependencies": { "github.com/owner/repo": "1.2.0" },
  "replace": { "github.com/owner/repo": "../repo" }
}
```

`replace`はこのプロジェクトでだけ有効で、lockには書かれません。

### パッケージを作る

パッケージはgitリポジトリ1つです。フォルダ構成は次のとおりです。

```bash
repo/
├── hana.pkg.json
├── haja/
│   └── index.hj      ← ハジャのエントリポイント
└── kanade/
    └── index.knd     ← カナデのエントリポイント
```

エントリポイントはどちらか片方だけでも構いません。エントリポイントの中の関数とクラスを、ほかの人が`【github.com/owner/repo】から…を持ってこよう`で持っていきます。`hana.pkg.json`はパッケージ自身の情報です。

```json
{
  "name": "github.com/owner/repo",
  "version": "1.2.0",
  "dependencies": {
    "github.com/owner/other": "2.0.0"
  }
}
```

- `name`はリポジトリのパスと同じでなければなりません（違うとインストールが拒否されます）。
- `dependencies`は、このパッケージが必要とするパッケージと最小バージョンです。パッケージ同士がぐるぐると互いを必要とすると、インストールが拒否されます。
- エントリポイントのパスを変えるには、`"entry": {"kanade": "src/main.knd"}`のように書きます。
- **バージョンはgitのタグで決めます**。新しいバージョンを出すときは、`git tag v1.3.0`を作ってプッシュします。

### ネイティブライブラリを入れる

ハジャやカナデでは難しいことは、GoやCなどで作ったライブラリ（`.dll`、`.so`、`.dylib`）に任せられます。OSごとに用意しておいたファイルを`hana.pkg.json`に書きます。

```json
{
  "native": {
    "windows-amd64": {
      "file": "native/repo.dll",
      "url": "https://example.com/repo-windows-amd64.dll",
      "sha256": "…64桁…"
    },
    "linux-amd64": {
      "file": "native/librepo.so",
      "url": "https://example.com/librepo-linux-amd64.so",
      "sha256": "…64桁…"
    }
  }
}
```

`hana add`は**今のコンピューターのプラットフォームの分だけ**ダウンロードし、`sha256`が合っているか確認します。違えばファイルを捨ててインストールを止めます。リポジトリの中にファイルがすでに入っていれば（`file`があれば）ダウンロードしません。ライブラリが守るルールは、hanaリポジトリの`native/native.go`に書かれています。

### インストールスクリプト

用意したファイルを渡せず、インストールのときに自分でビルドしなければならないなら、インストールスクリプトを使えます。シェルを通さない**コマンドの配列**で書きます。

```json
{
  "scripts": {
    "install": ["go", "build", "-buildmode=c-shared", "-o", "native/repo.dll", "./native"]
  }
}
```

スクリプトはコンピューターで自由に動くプログラムなので、そのままでは**実行しません。**

- ユーザーが`hana add github.com/owner/repo --allow-scripts`で承認する必要があります。承認すると`hana.json`の`trustedScripts`に書かれます。
- 承認したスクリプトのハッシュが`hana-lock.json`に書かれます。スクリプトが変わると、承認し直すまで拒否されます。
- ほかのパッケージが必要として付いてきたパッケージのスクリプトは、自動では許可されません。パッケージごとに別々に承認します。
- スクリプトは`hana add`と`hana install`の中でだけ動きます。`hana run`は決して実行しません。
- スクリプトを実行する前に、どんなコマンドかを画面に表示します。

承認していないスクリプトは、飛ばして案内だけを表示します。スクリプトにはサンドボックスがないので、信頼できるパッケージにだけ承認してください。

### 知っておくこと

- パッケージの中の関数は、**同じパッケージのほかの関数**と、**そのパッケージが持ってきたほかのパッケージ**を自由に呼べます。持っていく人がそれらを別に持ってくる必要はなく、自分のスクリプトに同じ名前の関数があってもお互いに邪魔しません。
- ただし、パッケージの**一番上で作った変数**は関数の中から見えません。値を共有したいなら、その値を返す関数を作ってください。
- 別々の2つのパッケージが同じ名前の**クラス**を出すと、先に持ってきた方が残ります。クラス名は重ならないようにしてください。
- パッケージのパスは、`github.com/owner/repo`のように**ホスト名（ドットのある）とオーナーとリポジトリ名**でできていなければなりません。リポジトリの中のサブフォルダをパッケージにすることはできません。
- 非公開リポジトリはまだ対応していません。公開リポジトリだけをダウンロードします。
- Hanaランタイムが一緒に配る`timezone`のようなパッケージは、`hana add`なしで名前だけで持ってこられます。
- パッケージを使うプログラムを[実行ファイルにまとめる](/docs/hana/pack)と、パッケージのハジャ・カナデのコードはプログラムの中に入り、ネイティブライブラリは実行ファイルの隣に一緒に出力されます。
